Quick picture

Think of Kubernetes as a busy school:

  • Control plane = the principal’s office (makes the rules).
  • Nodes = classrooms (the computers).
  • Pods = students sitting at desks (running apps).
  • Deployments = class lists that say “keep 3 students here.”
  • Services = the hallway signs that help people find a class.

Helm and config version conflicts

Helm is a package manager for Kubernetes (like an app store). Helm 3 is compatible with the Kubernetes version it was built for, plus three older minors (n−3).

Sources: Helm version skew · Kubernetes version skew policy

Releases, prior versions, and upgrades

Kubernetes keeps the newest three minor versions in official support (N, N−1, N−2). You must upgrade one minor at a time. You cannot jump from 1.35 straight to 1.37.

  1. Read the release notes for the next minor version.
  2. Upgrade the control plane first (API server, then controller-manager and scheduler).
  3. Upgrade extra control-plane nodes if you have them.
  4. Upgrade worker node kubelets last. Kubelet may be up to three minors older than the API server, but never newer.
  5. Check add-ons: CNI, CSI, Ingress, Helm charts, and operators.

Learn Kubernetes — middle-school walkthrough

        

          
Imagine you run a pizza shop that suddenly gets famous. One oven is not enough. You hire more cooks (containers), put them in kitchens (nodes), and hire a manager (the control plane) who watches the orders and says “we need two more pepperoni pizzas.” That manager is Kubernetes.

          
Step 1 — Desired state. You write a file that says “I want 3 copies of my website.” Kubernetes stores that wish.

          
Step 2 — The API server hears you. Every tool, including this dashboard, talks to one front door called the API server.

          
Step 3 — Controllers compare wish vs reality. If only 2 copies are running, a Deployment controller starts a third Pod.

          
Step 4 — The scheduler picks a classroom. It looks at CPU and memory and places the new Pod on a Node that has room.

          
Step 5 — kubelet does the local work. On that Node, kubelet asks the container runtime (often containerd, sometimes Docker) to start the container.

          
Step 6 — A Service gives a stable name. Pods die and come back with new IPs. A Service is a permanent phone number that always points at healthy Pods.

          
Step 7 — You watch logs and metrics. When something breaks, logs tell the story. This dashboard’s Logs panel is that diary.
