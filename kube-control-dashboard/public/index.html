How to use this dashboard

1. Log in to your Kubernetes provider using its normal CLI.

2. Make sure kubectl get nodes works.

3. Start this dashboard. It reads the same kubeconfig.

4. Pick a context and namespace, then refresh.

5. Write actions are off by default. Turn them on at server startup only when you intend to change the cluster.

What “healthy” means here

This prototype checks basic Kubernetes signals: ready nodes, deployment availability, pod phase/ready containers, and Warning events.

It is not a replacement for Prometheus, OpenTelemetry, cloud monitoring, alerting, or SLOs. Think of it as a fast operations console.

Why upgrades have an order

The API server is the “school office.” Other components talk to it. Kubernetes has specific version-skew rules, so changing pieces in the wrong order can create unsupported combinations.

Managed services such as EKS, GKE, AKS, OpenShift, and IBM Cloud also add their own supported-version windows and upgrade procedures.
